# 로컬·원격 저장소 식별

근거: 사용자 요청. 공식 앱·기존 대화·결제 작업 보존.

- 개발 앱에 로컬 Lohtu와 맥미니 agent의 원격 Lohtu를 실제 등록한다. 목록에서 서로 다른 호스트 아이콘·이름·로컬/원격 표시를 확인한다.
- 각 저장소의 기본 채팅 상단에서 해당 저장소 이름·위치를 확인한다. 저장소 호스트를 Hermes 실행 호스트로 잘못 표시하지 않는다.
- 원격 연결이 끊겨도 원격 저장소가 로컬로 표시되지 않아야 한다. 소유권이 불명확하면 미확인으로 표시한다.
- 기존 애드센스 대화의 이력이 유지되고 기본 채팅으로 열리는지 확인한다. 공식 앱의 기존 웹 채널은 구분하여 보존한다.

## 모든 프로젝트의 기본 Hermes 채팅

- 준비: 개발 앱의 로컬·원격 Lohtu, 기존 결제 대화 보존. 원격 계정은 macmini-agent, 실제 Hermes는 기존 맥미니 Hermes를 사용한다.
- 입력: 각 호스트에 소유자만 읽을 수 있는 외부 ACP 등록을 설치하고 개발 앱 기본 에이전트를 Hermes로 설정한다. 환경변수 지정이 없으면 사용자 설정 디렉터리의 명시적 등록 파일만 읽는다.
- 기대: 실제 앱의 각 호스트 에이전트 목록에 Hermes가 나타나고 새 빈 작업공간을 열면 Hermes 기본 채팅이 열린다. 단순 터미널 또는 다른 에이전트로 조용히 대체하지 않는다.
- 입력: 등록 파일 누락, 잘못된 권한, 환경변수의 명시적 다른 경로를 시험한다.
- 기대: 기본 파일 누락은 추가 등록 없음, 잘못된 권한은 거부, 환경변수 경로 우선. 잘못된 명시적 경로를 기본 파일로 우회하지 않는다.
- 입력: 원격 Lohtu의 새 Hermes 채팅에서 파일·Chrome·결제 변경 없는 식별 응답을 요청한다.
- 기대: 맥미니 Hermes 응답이 웹탭이 아닌 기본 채팅에 표시되고 기존 대화가 유지된다.

- 입력: 최초로 선택하는 빈 원격 작업공간에서 기본 Hermes를 수동 선택하지 않고 프로젝트 행만 클릭한다.
- 기대: 원격 초기 화면 생성도 로컬과 같은 기본 채팅 선택 경로를 사용하고 Hermes 채팅 한 개만 열린다. 탐지 대기 중 작업공간을 이동하면 이전 작업공간에 새 화면을 만들지 않는다.
